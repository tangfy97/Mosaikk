# Collage Atelier UI/UX Audit

## Scope

- Platform: macOS AppKit shell with a local HTML/CSS/JavaScript editor.
- Primary journey: import from Finder/browser/clipboard, choose layout, crop and reorder images, annotate, preview, copy or export.
- Evidence: source inspection plus isolated browser rendering at 1440 x 960 and 640 x 900 using six generated test images.
- States checked: empty and populated canvas, selected image, controls panel, inspector, Add and More menus, preview, delete/undo, reorder/undo, per-image fit, reload restore, and responsive split view.
- Not checked: VoiceOver announcement quality, browser-authenticated image URLs, very large HEIC files, and multi-monitor native window behavior.

## Product Direction

Collage Atelier should feel like a lightweight Mac utility: the canvas owns the screen, common actions appear next to the selected object, advanced controls are requested rather than imposed, and every destructive edit has a recovery path. Motion is used only to connect selection with its controls. System typography, restrained neutral surfaces, sage action color, and compact 32-42 px controls remain the visual foundation.

## Findings

| ID | Priority | Finding and evidence | Resolution | Verification | Status |
| --- | --- | --- | --- | --- | --- |
| UX-01 | P1 | Importing or selecting an image automatically opened the full inspector. At 640 x 900 it covered most of the canvas and interrupted repeated browser-to-app collection. | Inspector is now opt-in. A compact contextual crop bar appears near the selected canvas instead. | Zero panels are visible after import at both audited sizes; the contextual toolbar reaches full opacity and remains near the canvas. | Fixed and verified |
| UX-02 | P1 | Closing the app discarded the collage without warning or recovery. | The current collage, image blobs, crop state, layout and annotations now autosave locally and restore on launch. | Three test images and their individual fit modes restored after reload. | Fixed and verified |
| UX-03 | P1 | Delete, replace, crop and layout changes had no undo path. | Added a 40-step undo/redo history with Command-Z and Shift-Command-Z, plus native Edit menu items. | Image reorder and deletion both restored correctly; redo path is wired to the same snapshot model. | Fixed and verified |
| UX-04 | P2 | Image order was effectively fixed unless users re-imported into slots. Direct drag could not be reused because dragging inside an image already means crop. | Added previous/next slot actions beside the canvas and Option-Arrow keyboard movement. Empty targets move; occupied targets swap. | First two images swapped and Command-Z restored the original order. | Fixed and verified |
| UX-05 | P2 | Fill/Fit appeared inside a selected-image inspector but changed every image, creating a mismatch between scope and result. | Fit mode is now stored per image, with the collage default used only as fallback. | Setting slot 1 to Fit produced `contain, cover, cover` and persisted after reload. | Fixed and verified |
| UX-06 | P2 | Import/export feedback lived mainly in the hidden controls panel, so common actions could appear silent. | The persistent bottom status region now receives action feedback and exposes an atomic status message. | Import, move, delete, restore and export paths update the visible status region. | Fixed and verified |
| UX-07 | P2 | Fixed layout presets did not respond to imported image count or source aspect. | Added Auto arrange, which evaluates image count, canvas ratio and median image ratio to choose a compact grid. | Three portrait test images changed the canvas from six slots to three; Command-Z restored six. | Fixed and verified |
| UX-08 | P2 | Preview moved focus to its close button but did not return focus on dismissal. | Preview now restores the prior focused control. Space provides a canvas-level Quick Look interaction when focus is not inside a control. | Closing preview returned focus to the Preview button. | Fixed and verified |
| UX-09 | P1 | The top bar collapsed important commands into unlabeled icons in split view. Users had to guess the meaning of Text, Highlight, Inspector and export controls. | Rebuilt the toolbar around explicit verbs: Layout, Photos, Paste, Add, Preview, Save PNG and Copy. Add combines insertion actions; More contains secondary window and output actions only when space is limited. | Labels remain visible at 1440 px and 640 px. Both menus fit inside the viewport, support Escape focus return, and have no overlap or horizontal overflow. | Fixed and verified |
| UX-10 | P2 | The selected-photo toolbar used compact symbols without communicating scope, so crop, order and destructive actions were hard to distinguish. | Added visible Move and Crop groups plus labeled Reset, Replace, Edit and Remove actions. Replaced internal terms such as slot and fit with Photo, Crop to fill and Show whole. | At both audited sizes the toolbar identifies the current photo and exposes every action without opening a panel. | Fixed and verified |
| UX-11 | P2 | A new canvas looked like an inactive blank grid and did not make the fastest starting actions obvious. | Added a focused empty state with Choose photos and Paste image while preserving drag and global paste support. | Empty state is visible on first load and disappears after import at both audited sizes. | Fixed and verified |
| UX-12 | P2 | Text, highlight, preview and export competed visually with the primary photo workflow, making the app feel crowded. | Applied progressive disclosure: creation commands live in Add, secondary commands collapse into More only in split view, and selection-specific actions stay next to the canvas. | Wide view exposes Preview and Save PNG directly; 640 px split view moves them into More and keeps the primary toolbar readable. | Fixed and verified |
| UX-13 | P1 | Repeated paste and drop actions reused the selected slot, so a second image could silently overwrite the first instead of continuing in reading order. | All ordinary imports now target the next empty photo space, starting to the right of the current photo and wrapping only when needed. Existing photos are replaced only through the explicit Replace command. | Seven sequential imports filled Photo 1 through Photo 7 without changing earlier files; reselecting Photo 1 still inserted at the next empty position. | Fixed and verified |
| UX-14 | P1 | The native window had only a small, inconsistent drag target in split view, making the app appear stuck on screen. | Added an 11 px native drag strip across the safe top edge, widened the narrow brand zone from 40 px to 78 px, and added a visible grip. Web pointer events now ask AppKit to begin the drag directly, with a native overlay as fallback. All regions avoid traffic lights and toolbar controls. | The AppKit target compiles successfully and the rebuilt app exposes both drag paths. Physical pointer testing remains recommended across multiple monitors. | Fixed, native QA pending |
| UX-15 | P2 | After the first import, the interface did not explain where the next paste or drop would land. Import feedback was also overwritten as soon as image metadata loaded. | The next empty cell is now labeled Next photo. Dragging shows Add as Photo N and highlights the actual destination; success feedback persists briefly and states the next import number. A full grid adds another row automatically. | Drop preview targeted Photo 5 while hovering an occupied Photo 1; a seventh paste expanded the layout from 2 x 3 to 3 x 3. | Fixed and verified |

## Remaining Opportunities

- Add a project file format only if users need multiple named collages; autosave intentionally optimizes for one fast working canvas.
- Add multi-select and batch crop only after real workflows show repeated per-image adjustment is a dominant task.
- Consider a native share sheet after export destinations become clearer; Copy remains the fastest current handoff.
- Validate VoiceOver wording and switch-control order in a dedicated assistive-technology pass.
